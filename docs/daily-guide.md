## 0. 다른 루틴을 방해하지 않기 (가장 먼저, 모든 규칙보다 우선)

1. **사용량**: 남은 주간 사용 한도가 30% 미만이면 아무것도 하지 않고 "사용량 보호로 건너뜀"이라고만 보고한다 (자격증 추가 루틴이 우선이다).
2. **시간**: 한국시간 03:30 이후에는 main 에 push 하지 않는다. 그때까지 못 끝내면 아무것도 push 하지 않고 끝낸다 (다음 날 다시 쓴다). 04:00~05:00, 13:24~14:24 에는 어떤 경우에도 push 하지 않는다.
3. **건드려도 되는 파일은 두 곳뿐**: `data/guides/{ko 또는 en}/{slug}.json`(새 파일 1개) 과 `reports/guide-progress.md`(한 줄 추가).
   코드·설정·다른 데이터·문서·다른 루틴의 기록·`data/cert-queue.json`·자격증 폴더는 읽기만 하고 절대 고치지 않는다.
   (검사가 실패하면 원인이 이 루틴의 글이 아니어도 고치지 않는다. 기록만 남기고 끝낸다.)
4. **main 을 깨뜨리지 않기**: push 전에 `npm run validate` → `npm test` → `npm run build` → `npm run check:meta` 가 모두 통과해야 한다.
   하나라도 실패하면 main 에 push 하지 않고 `routine/guide-{날짜}` 브랜치에만 push 한 뒤 "반영 보류"로 기록한다.
5. git: 커밋 1개(`guide: add {slug}`), `git pull --rebase` 후 main 에 push. 강제 push·reset 금지. PR 을 만들지 않는다.
6. 하위 에이전트를 만들지 않는다. 빌드·검사는 실패 항목만 출력해서 확인한다.
7. 예약 작업(다른 루틴·이 루틴 자신)의 설정은 보기만 하고 바꾸지 않는다.

## 수험 정보란 (컨셉·목적)

- **컨셉**: 자격증달인 이용자가 문제 풀이 전후에 읽는 "시험 준비 안내서". 블로그식 잡글이 아니라, 공식 정보를 쉽게 풀어 정리한 실용 글.
  다른 사이트에 흔한 글을 다시 쓰지 않는다. 공식 정보 + 이 사이트의 단원 분석(`chapters.json`)을 엮어 **여기서만 볼 수 있는 정리**를 만든다.
- **목적**
  1. 검색 유입: "지게차 시험 일정", "전기기능사 공부 순서" 같은 검색어로 문제 페이지만으로는 못 잡는 방문자를 데려온다.
  2. 사이트 신뢰도: 꾸준히 업데이트되는 전문 사이트로 인식되게 한다 (애드센스 심사에도 도움).
  3. 문제풀이로 연결: 글을 읽은 사람이 관련 자격증 문제를 바로 풀게 한다 (`certIds` → 글 아래 "문제 풀기" 버튼, 자격증 페이지에는 "이 자격증 수험 정보" 링크가 자동으로 붙는다).
- **가장 큰 위험은 품질이다.** 틀린 날짜 하나가 사이트 신뢰를 깎고, 비슷하거나 얕은 AI 글이 쌓이면 구글이 사이트 전체를 낮게 평가한다.
  그래서 **좋은 글을 못 쓰는 날은 쓰지 않는다** ("건너뜀"으로 기록). 매일 올리는 것보다 틀리지 않는 것이 우선이다.

## 2. 오늘의 언어·주제 정하기

**언어는 요일로, 글 종류는 언어마다 6가지를 차례로 돌린다.** 한국어·영어 모두 6가지 글 종류를 다 쓴다.

- 언어: 월·화·수 = 한국어, 목·금·토·일 = 영어.
- 글 종류 차례 (한국어·영어 따로 센다):

| 차례 | 분류 (`category`) | 글 종류 |
|---|---|---|
| 1 | `schedule` | 원서접수·시험일 D-day 정리 (회차, 접수 기간, 시험일, 발표일. D-day 는 `publishedAt` 기준이라고 밝힌다) |
| 2 | `pass-guide` | 자격증별 합격률·난이도·공부 기간 가이드 (아래 "합격 전략 글 주의") |
| 3 | `change` | 출제기준 변경, 법령 개정 정리 |
| 4 | `exam-tips` | CBT(컴퓨터 시험) 시험장 팁, 필기→실기(1차→다음 단계) 준비 순서 |
| 5 | `career` | 취득 후 활용 — 수당·가산점·취업 (미국은 면허 발급 절차, 그 자격이 필요한 일, 공식 근거가 있는 우대) |
| 6 | `concept` | 주제 깊이 보기 — 특정 주제 하나를 깊게 설명 (아래 "깊이 보기 글 주의") |

- **오늘의 차례**: `reports/guide-progress.md` 에서 오늘 언어의 가장 최근 행(건너뜀 포함)의 분류 **다음 차례**. 6 다음은 1. 그 언어의 기록이 없으면 1부터.
- **대체 규칙**: 오늘 차례를 공식 출처로 제대로 쓸 수 없으면(다가오는 일정 공고가 없음, 확인되는 제도 변경이 없음, 미국 상시 시험이라 일정 글이 맞지 않음 등) 그다음 차례로 넘어가 쓴다.
  기록의 분류 칸에는 **실제로 쓴 분류**를 적고 비고에 "{원래 차례} 확인 안 됨 → 다음 차례"를 적는다. 다음 날은 실제로 쓴 분류의 다음 차례부터 이어진다.
- **합격 전략 글 주의**: 합격률은 공식 통계(예: 큐넷 종목별 합격률)에서 확인한 것만 연도와 함께 쓴다. 확인 못 하면 합격률 없이 쓴다.
  "난이도"는 느낌으로 쓰지 않고 객관적인 근거(합격 기준, 과락 유무, 문항 수·시험 시간, 공식 합격률)로 설명한다.
  "공부 기간"은 "보통 몇 주면 합격" 같은 근거 없는 단정을 하지 않는다. 대신 이 사이트의 단원·문항 구성을 바탕으로 한 **계획 예시**(예: 하루 10문제씩이면 전 단원을 몇 주에 한 번 돈다)로 쓰고, 예시라고 밝힌다.
- **취득 후 활용 글 주의**: 회사마다 다른 수당 금액·연봉은 쓰지 않는다. 가산점·우대는 법령·공고·기관 규정에서 확인한 것만 쓴다.
- **깊이 보기 글 주의**: 자격증 페이지의 "개념 정리"(`data/certs/{나라}/{slug}/concepts.json`)·단원 핵심정리(`chapters.json` 의 `keyPoints`)와 **겹치지 않게** 쓴다.
  - 쓰기 전에 그 자격증의 `concepts.json`·`keyPoints` 를 읽는다. 거기 있는 요약을 다시 정리하는 글은 쓰지 않는다.
  - 범위가 좁고 구체적인 주제 **하나**를 고른다. 예: "지게차 유압 장치에서 밸브 세 종류는 무엇이 다른가", "전기기능사 접지 공사 종류가 바뀐 이유", "CDL air brake 의 spring brake 는 언제 걸리나".
    "핵심 개념 총정리", "꼭 알아야 할 개념 10가지" 같은 넓은 요약 글은 쓰지 않는다.
  - 요약이 아니라 **왜 그런지, 어떻게 작동하는지, 현장에서는 어떤 모습인지, 무엇과 헷갈리는지, 시험에서는 어떻게 묻는지**까지 풀어 쓴다.
    단계별 설명이나 계산 예시가 있으면 넣는다. 원리·수치는 공식 기준·법령·교재 수준의 확립된 내용만 쓰고, 법령 수치는 3장대로 확인한다.
  - 같은 자격증의 깊이 보기 글끼리도 주제가 겹치지 않게 한다.

- 한국어는 `data/certs/KR/`, 영어는 `data/certs/US/` 중 `chapters.json` 이 있는 자격증(문제가 있는 자격증)에서 고른다.
- **반복 금지**: `reports/guide-progress.md` 를 보고, 같은 언어에서
  - 최근 14일 안에 다룬 자격증은 고르지 않는다.
  - 같은 자격증 + 같은 분류는 90일 안에 다시 쓰지 않는다.
  - 같은 제목·같은 slug 는 다시 쓰지 않는다. 쓰기 전에 같은 언어의 기존 글 제목·소제목을 훑어보고, 같은 각도의 글이 있으면 다른 주제로 바꾼다.
- 응시자가 많은 자격증을 자주, 그 밖의 자격증을 고르게 섞는다.
  - 한국: 지게차·굴착기·전기기능사·산업안전·컴활·한국사·공인중개사·운전면허 필기 등
  - 미국: DMV 필기(permit)·CDL·NCLEX·ServSafe·시민권 시험(USCIS civics)·ASVAB·CompTIA 등
- 미국 `schedule` 은 정해진 시험일·접수 마감이 공식으로 공고되는 시험(예: 시험 기간이 정해진 시험)만 쓴다. 상시 시험뿐이면 대체 규칙으로 넘어간다.

## 3. 정확성 규칙 (아무도 검토하지 않으므로 가장 엄하게)

- 일정·응시료·합격 기준·면제 기간·법령 수치 같은 **사실은 공식 출처에서 오늘 확인한 것만** 쓴다.
  - 한국 공식 출처: 시행기관 사이트(큐넷·한국산업인력공단, 대한상공회의소, 국사편찬위원회, 한국데이터산업진흥원, 한국보건의료인국가시험원, 금융투자협회, 도로교통공단 등), 국가법령정보센터(law.go.kr), 정부 부처 사이트.
  - 미국 공식 출처: 시험 시행기관(예: NCSBN, CompTIA, ServSafe/National Restaurant Association, AICPA·NASBA), 주 DMV·주 정부 사이트, 연방 기관(USCIS, FMCSA, EPA, OSHA 등), eCFR.
  - 블로그·학원·문제풀이 사이트·언론 기사는 근거로 쓰지 않는다 (기사는 공식 출처를 찾는 실마리로만 쓴다).
- 이 저장소의 자격증 데이터(`meta.json` 의 `examInfo`·`content`, `chapters.json`)는 이미 검증된 정보이므로 근거로 써도 된다.
  단원별 문항 수는 "이 사이트의 단원 분석 기준 약 N문항"처럼 어림값이라고 밝힌다.
- 확인하지 못한 사실은 쓰지 않는다. 필요하면 "정확한 일정은 큐넷 공고에서 확인하세요"처럼 공식 확인을 안내한다.
- 아직 공고되지 않은 회차의 일정, 해마다 바뀌는 응시료는 쓰지 않거나 "{기준일} 공고 기준"을 붙인다. 일정 글은 제목에 연도·회차를 넣는다.
- 합격률·응시자 수 같은 통계는 공식 통계에서 확인한 경우에만, 연도와 함께 쓴다. **지어낸 수치·후기·경험담·"많은 합격자가 ~" 같은 근거 없는 일반화 금지.**
- 회사마다 다른 수당 금액, 연봉, 취업률은 쓰지 않는다. 가산점·우대는 법령·공고·기관 규정에서 확인한 것만 쓴다.
- 의료·법률 시험(NCLEX, 공인중개사 등)이라도 글은 **시험 정보**에 머문다. 실제 진료·법률 판단처럼 읽힐 조언은 쓰지 않는다.
- `basisDate` 는 오늘(출처를 확인한 날), `sources` 에는 실제로 열어서 확인한 공식 출처만 적는다 (`checkedAt` = 오늘). 출처를 열 수 없었으면 그 출처에 기댄 문장을 쓰지 않는다.
- **사실 대조 (게시 전 필수)**: 글의 숫자·날짜·기관명·절차 문장을 하나씩 뽑아 "문장 → 출처 → 출처의 해당 내용"으로 맞춰 본다 (작업 메모로만, 파일로 남기지 않는다).
  맞지 않거나 근거가 없는 문장은 고치지 말고 지운다. 지운 뒤 분량이 모자라면 그날은 쓰지 않는다.

## 4. 글 쓰는 법

- 파일: `data/guides/{ko 또는 en}/{slug}.json`, 형식은 `lib/schemas.ts` 의 `guideSchema`. 예시: `data/guides/ko/forklift-operator-written-study-plan.json`.
- `slug`: 영문 소문자·숫자·하이픈 (예: `electrician-craftsman-2026-4th-schedule`, `cdl-air-brakes-test-day-checklist`). 한 번 정하면 바꾸지 않는다.
- `publishedAt` = 오늘(한국시간). `certIds` 에 관련 자격증 slug 1~3개 (같은 나라 자격증만).
- `title`: 사람들이 검색할 말로, 자격증 이름을 앞에 (60자 이하). `description`: 무엇을 알 수 있는지 한두 문장 (160자 이하).
- `intro` 1문단 + `sections` 4~7개 + `faq` 2~4개.
  - 한국어: 본문 띄어쓰기 빼고 **1,200자 이상**(검사가 막는다), 보통 1,800~3,000자.
  - 영어: 본문 공백 빼고 **2,400자 이상**(검사가 막는다), 보통 700~1,200단어.
- 독자는 40~50대 현장 근무자다. 쉬운 말, 짧은 문장, 전문 용어는 처음 나올 때 풀어 쓴다. 영어도 plain English 로 쓴다.
- body 문법: 문단(빈 줄로 구분), `**굵게**`, `- ` 목록, `1. ` 번호 목록만. HTML·표·링크 문법은 쓰지 않는다 (출처 링크는 `sources` 에).
- 작성 주체("AI 작성 · 운영진 관리")와 출처 목록은 화면이 자동으로 붙인다. 본문에 따로 적지 않는다.

### 품질 기준 (얕은 글·비슷한 글 금지)

- **섹션마다 그 자격증만의 구체적인 내용**(시험 구성, 단원별 비중, 헷갈리는 개념의 차이, 공식 절차의 단계, 기한)을 하나 이상 담는다.
  "꾸준히 공부하세요", "기출을 많이 푸세요", "컨디션 관리가 중요합니다" 같은 어디에나 맞는 문장으로 섹션을 채우지 않는다.
- **독자가 바로 할 행동**이 있어야 한다 (언제 접수할지, 오늘 무엇부터 공부할지, 시험 전날 무엇을 챙길지). 마지막 섹션이나 FAQ 앞에 분명하게 적는다.
- 다른 글과 문장·문단 구조를 돌려쓰지 않는다. 같은 분류의 글이라도 소제목을 그 자격증에 맞게 새로 정한다.
- FAQ 는 실제로 검색할 만한 질문만, 본문과 같은 내용을 되풀이하지 않는다.
- 쓸 거리가 모자라면 분량을 늘리지 말고 주제를 좁히거나(예: "필기 전체" 대신 "법규 숫자 정리") 그날은 쓰지 않는다.

### 게시 전 마지막 점검 (하나라도 "아니오"면 고치거나, 못 고치면 게시하지 않는다)

1. 모든 숫자·날짜·절차가 3장 사실 대조를 통과했는가?
2. 출처는 모두 공식 출처이고, 오늘 실제로 열어 본 것인가?
3. 지어낸 통계·후기·경험담·근거 없는 일반화가 없는가?
4. 섹션마다 그 자격증만의 구체적인 내용이 있는가? 다른 자격증 이름으로 바꿔도 말이 되는 섹션은 없는가?
5. 독자가 바로 할 행동이 있는가?
6. 기존 글과 제목·각도·문장이 겹치지 않는가?
7. 50대 현장 근무자가 처음 읽어도 이해되는 말인가?
