1. **사용량**: 남은 주간 사용 한도가 30% 미만이면 아무것도 하지 않고 "사용량 보호로 건너뜀"이라고만 보고한다 (자격증 추가 루틴이 우선이다).
2. **시간**: 한국시간 03:30 이후에는 main 에 push 하지 않는다. 그때까지 못 끝내면 아무것도 push 하지 않고 끝낸다 (다음 날 다시 쓴다). 04:00~05:00, 13:24~14:24 에는 어떤 경우에도 push 하지 않는다.
3. **건드려도 되는 파일은 두 곳뿐**: `data/guides/ko/{slug}.json`(새 파일 1개) 과 `reports/guide-progress.md`(한 줄 추가).
   코드·설정·다른 데이터·문서·다른 루틴의 기록·`data/cert-queue.json`·자격증 폴더는 읽기만 하고 절대 고치지 않는다.
   (검사가 실패하면 원인이 이 루틴의 글이 아니어도 고치지 않는다. 기록만 남기고 끝낸다.)
4. **main 을 깨뜨리지 않기**: push 전에 `npm run validate` → `npm test` → `npm run build` → `npm run check:meta` 가 모두 통과해야 한다.
   하나라도 실패하면 main 에 push 하지 않고 `routine/guide-{날짜}` 브랜치에만 push 한 뒤 "반영 보류"로 기록한다.
5. git: 커밋 1개(`guide: add {slug}`), `git pull --rebase` 후 main 에 push. 강제 push·reset 금지. PR 을 만들지 않는다.
6. 하위 에이전트를 만들지 않는다. 빌드·검사는 실패 항목만 출력해서 확인한다.
7. 예약 작업(다른 루틴·이 루틴 자신)의 설정은 보기만 하고 바꾸지 않는다.

## 3. 정확성 규칙 (아무도 검토하지 않으므로 가장 엄하게)

- 일정·응시료·합격 기준·면제 기간·법령 수치 같은 **사실은 공식 출처에서 오늘 확인한 것만** 쓴다.
  공식 출처: 시행기관 사이트(큐넷·한국산업인력공단, 대한상공회의소, 국사편찬위원회, 한국데이터산업진흥원, 한국보건의료인국가시험원, 금융투자협회, 도로교통공단 등), 국가법령정보센터(law.go.kr), 정부 부처 사이트.
  블로그·학원·문제풀이 사이트·언론 기사는 근거로 쓰지 않는다 (기사는 공식 출처를 찾는 실마리로만 쓴다).
- 이 저장소의 자격증 데이터(`meta.json` 의 `examInfo`·`content`, `chapters.json`)는 이미 검증된 정보이므로 근거로 써도 된다.
  단원별 문항 수는 "이 사이트의 단원 분석 기준 약 N문항"처럼 어림값이라고 밝힌다.
- 확인하지 못한 사실은 쓰지 않는다. 필요하면 "정확한 일정은 큐넷 공고에서 확인하세요"처럼 공식 확인을 안내한다.
- 합격률·응시자 수 같은 통계는 공식 통계에서 확인한 경우에만, 연도와 함께 쓴다. 지어낸 수치·후기·경험담 금지.
- `basisDate` 는 오늘(출처를 확인한 날), `sources` 에는 실제로 열어서 확인한 공식 출처만 적는다 (`checkedAt` = 오늘).
- 쓴 뒤 처음부터 다시 읽으며 사실 문장마다 출처와 맞는지 한 번 더 확인한다. 맞지 않거나 근거가 없는 문장은 지운다.

## 4. 글 쓰는 법

- 파일: `data/guides/ko/{slug}.json`, 형식은 `lib/schemas.ts` 의 `guideSchema`. 예시: `data/guides/ko/forklift-operator-written-study-plan.json`.
- `slug`: 영문 소문자·숫자·하이픈 (예: `electrician-craftsman-2026-4th-schedule`). 한 번 정하면 바꾸지 않는다.
- `publishedAt` = 오늘(한국시간). `certIds` 에 관련 자격증 slug 1~3개 (글 아래 문제풀이 바로가기가 생긴다).
- `title`: 사람들이 검색할 말로, 자격증 이름을 앞에 (60자 이하). `description`: 무엇을 알 수 있는지 한두 문장 (160자 이하).
- `intro` 1문단 + `sections` 4~7개 + `faq` 2~4개. 본문은 띄어쓰기 빼고 **1,200자 이상**(검사가 막는다), 보통 1,800~3,000자.
- 독자는 40~50대 현장 근무자다. 쉬운 말, 짧은 문장, 전문 용어는 처음 나올 때 풀어 쓴다.
- body 문법: 문단(빈 줄로 구분), `**굵게**`, `- ` 목록, `1. ` 번호 목록만. HTML·표·링크 문법은 쓰지 않는다 (출처 링크는 `sources` 에).
- 글마다 독자가 바로 할 수 있는 행동(무엇부터 공부할지, 언제 접수할지)이 있어야 한다. 다른 글과 문장을 돌려쓰지 않는다.
- **얕은 글 금지**: 어디서나 볼 수 있는 일반론("꾸준히 공부하세요", "기출을 많이 푸세요")으로 채우지 않는다.
  그 자격증만의 구체적인 내용(시험 구성, 단원별 비중, 헷갈리는 개념, 공식 절차)을 섹션마다 하나 이상 담는다. 쓸 거리가 부족하면 주제를 좁힌다.
- `career` 글의 자격수당·가산점·채용 우대는 법령·공고·기관 규정에서 확인한 것만 쓴다 (예: 공무원 채용 가산점은 해당 법령·인사혁신처 자료). 회사마다 다른 수당 금액은 쓰지 않는다.
- 작성 주체("AI 작성 · 운영진 관리")와 출처 목록은 화면이 자동으로 붙인다.
