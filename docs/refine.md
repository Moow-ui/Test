## 0. 원칙 (어기면 그 자격증은 올리지 않는다)

1. **바꾸지 않는 것**: 주소(slug·단원 id), 페이지 제목·설명 문구(`lib/seo.ts`·`messages`), 화면 구성(`app/`·`components/`·`lib/`·`scripts/` 코드), 문제 id·문제 내용.
   수천 페이지의 제목을 한꺼번에 바꾸면 그것만으로 다시 평가를 받는다. **본문 데이터만** 고친다.
2. **그 자격증 데이터에서 나온 내용만 쓴다**: 이 단원 문제의 정답·해설·틀린 선지, 공식 출제기준·법령·주(州) 매뉴얼.
   어느 자격증에나 붙일 수 있는 일반 문장("꾸준히 공부하면 합격할 수 있습니다" 등)은 쓰지 않는다. 확인할 수 없는 합격률·통계는 쓰지 않는다.
3. **억지로 채우지 않는다**: 확신이 없는 함정은 쓰지 않는다. 함정이 없는 단원은 소개(`summary`)·요점을 그 단원 문제에 근거해 늘려 기준을 채운다.
4. 쉬운 말 (50대 현장 근무자 기준). 미국 자격증은 영어.
5. 고친 문장은 모두 작성과 분리된 검증을 통과해야 올린다 (4번).

## 1. 고르기

1. `reports/refine-progress.md` 의 "이어서 할 작업"에 자격증이 있으면 그것 (`routine/refine-{slug}` 브랜치나 1일차 커밋에서 이어 한다).
2. 없으면 "순서" 표에서 상태가 비어 있는 맨 위 자격증.
3. 단원이 25개 이상이면 이틀에 나눈다: 1일차는 앞쪽 절반 단원만 다듬어 `refine: {slug} (1/2)` 로 올리고 (`refinedAt` 은 적지 않는다), "이어서 할 작업"에 적는다. 2일차에 나머지를 끝내고 `refinedAt` 을 적는다.
4. 같은 날 주간 점검 루틴이 그 자격증을 고치고 있으면(`git log` 에 오늘 `maint: {slug}`) 다음 자격증을 고른다.

## 2. 재기 (전)

`npm run check:unique -- {slug}` 결과(문장 / 다른 자격증과 같은 문장 / 요점↔개념 정리 겹침 / 글이 짧은 단원 / 함정 있는 단원)를 기록용으로 적어 둔다.

## 3. 다듬기 (`chapters.json`, 필요하면 `concepts.json`)

단원마다 아래를 한다.

1. **자주 틀리는 함정 `pitfalls` 2~3개** (`docs/data-rules.md` 3장):
   - 그 단원 문제의 **틀린 선지** 가운데 수험생이 실제로 고르기 쉬운 것(숫자 혼동, 비슷한 용어, 예외 조건)을 고른다.
   - `trap` = 수험생의 틀린 생각을 한 문장으로 ("점멸 노란불이면 멈춰야 한다"). 문제 문장을 그대로 옮기지 않는다.
   - `fact` = 바른 내용 + 왜 헷갈리는지 1~2문장. 그 문제의 정답·해설과 같은 사실만 쓴다.
   - 법령·수치가 들어가면 그 문제의 해설·개념 카드의 출처와 같은 기준이어야 한다.
2. **요점과 개념 정리가 같은 문장을 쓰지 않게**: 단원 핵심정리(`keyPoints`)는 "외울 것"(숫자·조건·구분 위주의 짧은 문장),
   개념 정리(`concepts.json` 의 summary·카드)는 "설명"이다. 겹치는 문장은 **요점 쪽을** 다른 각도(숫자·조건·비교)로 고쳐 쓴다. 사실은 바꾸지 않는다.
   요점을 고쳐도 뜻이 같아질 수밖에 없으면 개념 정리 문장을 고치고, 그 단원은 다시 검증한 뒤 `verifiedAt` 을 오늘로 바꾼다.
3. **다른 자격증과 같은 문장 줄이기**: 검사가 알려 주는 겹치는 자격증(예: 다른 주 DMV)과 같은 문장은
   그 자격증에만 맞는 표현으로 고친다. DMV·주별 시험은 **그 주에만 있는 규칙**(벌점, 혈중알코올 기준, 면허 단계, 벌금 등)을
   그 주 공식 매뉴얼에서 확인해 넣는다 (출처는 `meta.json` 의 `sources` 에 있는 것, 없으면 더한다).
4. **단원 글이 짧으면** (`check:unique` 의 "글이 짧은 단원"): 함정을 더하거나, `summary` 에 이 단원에서 어떤 문제가 나오는지(이 단원 문제들의 유형)를 1~2문장 더한다.
5. **기준 연도**: 그 자격증의 공식 출제기준(또는 주 매뉴얼) 페이지를 열어 올해에도 지금 기준 그대로임을 확인했으면 `meta.json` 의 `basisYear` 를 올해로 적는다.
   열리지 않거나 확인하지 못하면 적지 않는다 (화면에는 추가한 해가 나온다). 이것 때문에 멈추지 않는다.
6. **그림 (그림 보강을 여기에 합쳤다, 2026-11-03)**: 그 자격증의 `visualNeed` 가 `high`·`medium` 이고 `reports/image-progress.md` 의 "다음 할 일"에 그 자격증 단원이 있으면,
   그 가운데 1단원을 [daily-routine.md](daily-routine.md) 2-2 의 2~3·5 대로 한다 (커밋은 따로 `images: add {slug} {chapterId}`). 사용량이 모자라면 건너뛴다 (실패 아님).

7. **단원 페이지 합치기 (2026-11-03 회장 결정, 자격증별로 다듬는 날 한다)**: 단원마다 페이지가 둘(단원 핵심정리 `/{단원}`, 개념 정리 단원 `/concepts/{단원}`)이라
   같은 내용이 겹치고 검색 노출이 둘로 나뉜다. 서치 콘솔에서 노출이 더 많은 **개념 정리 단원 페이지로 합친다.**
   - `meta.json` 에 `mergedAt` = 오늘을 적으면 코드가 저절로: 개념 정리 단원 페이지가 핵심정리(요점)·함정·출제 비중·공개 기출 기록·대표 문제 6개·풀기 버튼까지 보여 주고,
     `/{단원}` 은 만들지 않고 `/concepts/{단원}` 으로 영구 이동(301)하며, 사이트 지도·사이트 안 링크도 바뀐다. 코드는 고치지 않는다.
   - 합치기 전에 데이터를 정리한다: 함정이 있는 단원은 개념 정리의 "시험 포인트"를 합친 페이지에 싣지 않으므로(개념서 `/concepts` 에는 그대로 있다) 요점(`keyPoints`)에 빠진 사실이 없는지 본다.
     함정이 없는 단원은 요점 + 시험 포인트가 한 목록으로 나오므로 같은 말이 두 번 나오지 않게 요점을 고친다.
   - **개념 정리가 없는 단원**(`concepts.json` 에 없거나 `verifiedAt` 이 없음)은 합칠 곳이 없다. 그 단원 개념 정리를 [add-cert.md](add-cert.md) A-6-1 대로 써서 검증받는다.
     못 하면 그 단원은 지금 페이지(`/{단원}`)가 그대로 남는다 (실패 아님. "기록" 비고에 `합치기 제외 단원 N`).
   - 개념서(`/concepts`, 모든 단원이 한 페이지에 나오는 책)는 바꾸지 않는다.
   - 확인: `npm run build` 뒤 그 자격증의 `/{단원}` 이 `.next/server/app/{ko|en}/cert/{slug}/` 에 없고, `npm run check:meta` 통과.

## 4. 검증 (필수, 작성과 분리)

1. 새로 쓰거나 고친 문장만 모은 파일을 만든다: 단원마다 `pitfalls`, 고친 `keyPoints`·`summary`, 고친 개념 정리 문장.
2. **그 파일 + 그 단원 문제(정답·해설 포함) + 공식 출처 주소**만 받은 별도 에이전트(하위 에이전트)가 문장마다 확인한다:
   ① 사실이 맞는가 ② 그 단원 문제의 정답·해설과 어긋나지 않는가 ③ `trap` 이 정말 틀린 생각인가(맞는 말을 함정으로 적지 않았나) ④ 근거 없는 수치·통계가 없는가.
3. FAIL 문장은 고쳐서 다시 검증하거나 뺀다. 확신이 없으면 뺀다.
4. 결과를 `reports/{YYYY-MM}/refine-verify-{slug}.md` 에 적는다: 문장 N · 통과 N · 수정 후 통과 N · 뺌 N, FAIL 문장과 사유.

## 5. 마무리·검사·올리기

1. `meta.json`: `refinedAt` = 오늘(한국시간), `mergedAt` = 오늘(3-7), `updatedAt` = 오늘 (sitemap 날짜가 바뀌어 구글·네이버가 그 자격증 페이지만 다시 가져간다).
2. 검사 (전부 통과해야 올린다):

   ```bash
   npm run check:unique -- {slug} && npm run validate && npm test && npm run build && npm run check:meta
   ```

3. 커밋 1개 `refine: {slug}` (그 자격증 폴더 + `reports/{YYYY-MM}/refine-verify-{slug}.md` + `reports/refine-progress.md`) → `git pull --rebase origin main` → push. 강제 push 금지.
4. `reports/refine-progress.md`: "순서" 표의 그 행에 날짜와 결과를 적고, "기록" 표에 전/후 수치를 한 줄 적는다.
5. 실패하면 그 자격증 변경을 되돌리고 "순서" 표 상태에 `재시도` 를 적는다. 두 번 실패하면 `건너뜀`(사유)으로 적고 다음 날은 다음 자격증을 한다.
   사용량·시간이 모자라면 `routine/refine-{slug}` 브랜치에 push 하고 "이어서 할 작업"에 적는다 (실패로 세지 않는다).

## 6. 새 자격증은 처음부터 이 기준으로

2026-11-04 이후 추가하는 자격증은 [add-cert.md](add-cert.md) A-6-2 대로 처음부터 함정·고유 내용을 갖추고 `refinedAt` = `mergedAt` = `addedAt` 을 적는다 (단원 페이지도 처음부터 하나).
